# Chatbot・FAQ改善の反映手順

この変更はローカル実装です。GitHub push、本番デプロイ、本番DB変更は未実施です。

## DB

- 既存の20260905統合アップグレード済み環境には、`supabase/migrations/20260906_chatbot_experience.sql`を全体で適用する。
- 新規環境は更新済み`supabase/schema.sql`を使用する。
- DBを先に更新してからアプリをデプロイする。既存カラム・制約・旧upsertキーを残す追加型マイグレーションで、旧版アプリと共存する。
- 新規取り込みではファイル名を含む出典ハッシュを保存し、同じ本文でもファイル別に独立して参照できる。既存資料を自動削除しない。
- 新規RPCはservice_roleだけに実行許可し、更新RPCはactorの現在権限も検証する。

## 検索データ

- `GEMINI_API_KEY`が必要。Embeddingは`gemini-embedding-001`・768次元に固定し、登録と検索で統一する。
- 管理画面の一覧で「検索データ未作成」のMarkdownを同名で再取り込みする。
- 公開FAQはFAQ管理の「検索データを更新・再試行」で初回生成する。以降のFAQ編集時は生成を試み、API障害時には本文を保存しキーワード検索を継続する。
- MarkdownはUTF-8、10ファイル・合計1,000,000バイト、各1,000件。件数は長文分割後の回答データ数。
- 各ファイルを順次処理し、Embeddingが全部生成できてからDB内で差し替える。API失敗・保存失敗は旧版を維持する。
- 応答タイムアウトや切断は結果不明として表示する。読み込み済み一覧を確認後に再試行する。同名ファイルの再試行で回答を重複登録しない。
- 長時間処理には実行環境の時間制限がある。大きなファイルをまとめて処理中に中断された場合は、未完了ファイルを分けて再試行できる。

## 回答の判定

- イベントはDBを優先。該当なし・取得失敗から一般回答へ流さない。
- 検索はキーワード・タイトル類似度と保存済みEmbeddingを併用する。高一致0.82（意味一致は0.88以上）、候補0.38以上、意味検索候補0.68以上を初期値とする。
- タイトルと質問の完全一致は直接回答。単一キーワードだけでは高一致にしない。中一致は最大3件を生成へ渡す。
- 類似度は確率ではない。実際の質問と期待回答の組を用いて、誤一致・取りこぼしを確認し閾値を調整する。
- 該当なしでは回答生成しない。一般回答は許可対象の質問のみ、本人・対象・質問・有効期限に結び付けたボタンから実行する。
- 一般回答生成も利用回数に含める。super_adminは上限対象外。
- 利用についての説明は折りたたみに配置。参照元などの技術情報はsuper_adminテスト画面だけに表示する。

## ローカル検証

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e:experience
```

ブラウザテストはローカルのテスト用DB応答を使用し、本番Supabaseや外部AIへ接続しない。SQLの検証は`supabase/tests/chatbot_experience.sql`をテストDB上で実行する。

本番反映後は実際の資料・API利用枠で検索品質、取り込み時間、スマホ実機のキーボード・ドラッグ・スワイプを確認する。公開設定はsuper_adminが確認後に切り替える。
